Personal project · fine-tuning pipeline

A chatbot fine-tuned to text like me.

The idea is easy to state and fiddly to execute: a model that replies the way I actually text — lowercase, two lines, no preamble — rather than the way an assistant imagines a person texts. Nearly all the interesting work is in the dataset, not the training.

Llama-3.2-3B-Instruct QLoRA Unsloth PEFT TRL Hugging Face FastAPI Python HTML/CSS/JS

The data is private, and stays that way

The training set is real correspondence between real people who never agreed to be published. None of it appears here. The exports, the parsed conversations, the JSONL splits and the trained adapter all stay on one machine and are excluded from version control. The adapter counts too — a model trained on private text can reproduce it, so the weights are treated as sensitive rather than as a build artefact. What follows is the method and my own source code.

The pipeline

Six steps, and only one of them is training

Messages become turns, turns become context-and-reply pairs, pairs become an adapter, and the adapter gets served behind a UI that reconstructs the training format exactly.

01Export

A shell step drives the open-source imessage-exporter binary over the local message database, writing one plain-text file per conversation. It needs Full Disk Access to run, which is a useful standing reminder of how sensitive the input is.

02Parse into turns

A block parser pulls timestamp, sender and body out of each export, then strips everything that would otherwise be learned as style: tapback reactions, attachment placeholders, link unfurls and leaked file paths. Consecutive messages from the same person merge into one turn, because that is what a turn actually is — people send three bubbles, not three messages.

03Build the dataset

A sliding window over each conversation takes the three prior turns as the user message, labelled Them: and Me:, and my own reply as the assistant message, under a fixed system prompt describing the voice. Replies shorter than two characters or longer than 200 are dropped — the long ones are several texts concatenated, and they teach the model to ramble.

04Fine-tune

4-bit QLoRA on Llama-3.2-3B-Instruct through Unsloth and PEFT, trained with TRL's supervised fine-tuning trainer. A second, alternate path uploads the same JSONL to a hosted fine-tuning API, so the dataset format is the only thing both routes have to agree on.

05Serve locally

A FastAPI server loads the base model in half precision, applies the LoRA adapter on top, and picks Apple Silicon, CUDA or CPU automatically. One POST endpoint takes a message plus history and returns a reply, sampled short and warm to match the register: 40 new tokens, temperature 0.8, top-p 0.9.

06Serve it locally

One HTML file, no framework and no dependencies, styled as a phone messaging app. It rebuilds the recent turns into exactly the shape the dataset used, which matters far more than it sounds like it should.

The interface

One HTML file, no dependencies

Shown below on its opening screen, as a static picture. No conversation is shown, because any conversation worth showing would be real.

The interface is deliberately unremarkable, and that is the point. It is a single file with no build step and no libraries: a status bar with a live clock, an avatar, grey bubbles for the other side and blue for the model, animated typing dots while a reply generates, and a text field.

The one non-cosmetic decision is in the JavaScript. Before each request it rebuilds the recent exchange into the same Them: / Me: layout that step three used to build the dataset. Get that wrong and the fine-tune looks like it failed, when really the model is just being asked a question in a format it never saw. If the server is not running, the page says so in a bubble rather than failing silently.

The panel to the right is a picture of the interface, not a working chat. The model only runs locally and there is no public way to talk to it — it is a small 3B fine-tune, and it is not good enough to put in front of people.

What I took from it

Two things, neither of them about hyperparameters

Format drift is the silent killer

The gap between "the model saw this format" and "the model sees this format now" is where personality fine-tunes quietly fail. The UI has to reconstruct the prompt the same way the dataset builder did, down to the labels. When it does not, the fine-tune looks broken and the weights are fine.

Cleaning beat tuning

Merging consecutive messages into turns and dropping replies over 200 characters changed the output register more than any learning rate did. Both look trivial written down. Both are judgements about what a conversational turn actually is.

And a third, about data

Building this made the handling rules obvious rather than abstract. The exports are named after real people, so even a directory listing is disclosure. The adapter can echo its training text, so it is not a shareable artefact. Those constraints shaped the project, and this page.
